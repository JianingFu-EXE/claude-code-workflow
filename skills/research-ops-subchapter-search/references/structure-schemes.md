# Structure Schemes

Use this reference during Phase 1.

## Validation Checks

Treat a user-supplied outline as acceptable only when it passes most of these checks:

- Each sibling subchapter is meaningfully distinct.
- Each leaf subchapter can support focused search strings.
- The structure covers the research problem without obvious blind spots.
- The granularity is stable enough to become a Zotero collection tree.
- The leaf count is high enough to avoid broad dumping, but low enough to remain reviewable.

## Default Scheme Set

When the user does not provide a structure, propose exactly three schemes unless the field requires another trio.

### 1. Chronological

Use when the field is driven by technology generations, policy eras, or theory evolution.

Three-sentence justification pattern:

1. Explain why historical sequencing changes the research questions or evidence base.
2. Explain why time-based segments reduce conceptual overlap between subchapters.
3. Tie the choice back to the user's brief, seed bibliography, or supplied outline.

### 2. Methodological

Use when the field is split by experimental design, modeling approach, measurement method, or evaluation technique.

Three-sentence justification pattern:

1. Explain why methods create cleaner search boundaries than applications or time periods.
2. Explain how method-based leaves support reproducible search queries and source comparison.
3. Tie the choice back to the user's brief, seed bibliography, or supplied outline.

### 3. Problem-Scale

Use when the field naturally divides by device, system, market, region, or deployment scale.

Three-sentence justification pattern:

1. Explain why scale changes the dominant constraints, data sources, or stakeholders.
2. Explain how scale-based leaves prevent mixing incompatible evidence.
3. Tie the choice back to the user's brief, seed bibliography, or supplied outline.

## Comparison Table

Always present a comparison table after the three schemes. Use these columns:

| Scheme | Best When | Strengths | Weaknesses | Search Implications |
| --- | --- | --- | --- | --- |
| Chronological | Technology or policy changed over time | Clear temporal narrative | Weak when methods dominate | Query by era, generation, or policy window |
| Methodological | Techniques define the field | Clean search strings and evidence comparison | Can hide deployment context | Query by method names, metrics, datasets |
| Problem-Scale | Constraints change by size or layer | Strong for engineering and systems reviews | Can split closely related methods | Query by scale, stakeholders, and system level |

## Output Rule

When the user refers to a "provided" reference artifact but none exists, say so plainly and base the justifications on the topic definition rather than inventing a source.
